# Agent 多商户规划截断修复计划

> 执行要求：使用 executing-plans 按任务执行，并遵循 test-driven-development；本次由当前会话执行。

**目标：** 多商户趋势问题生成完整规划，查询真实月度指标，明确可比较期间；规划失败不得标记成功。

**架构：** Provider 保留结束原因，服务端在现有两轮预算内恢复截断规划，未完成规划不签名。每个商户使用一次 trend 返回全部指标；综合阶段从已绑定的月度结果确定共同完整月份并计算加权指标。

**技术栈：** Python 契约与 Provider、Vue/TypeScript Agent session、现有 AG-UI 与只读数据库接口。

## 全局约束

- 每次最多两轮规划、最多六次工具调用，每批最多四次。
- 单个 HTTP 请求两轮共用 55 秒时限，每轮不超过 30 秒；浏览器首次规划等待 65 秒、第二轮等待 35 秒。
- 规划默认输出额度 4096，环境配置限制在 1024–8192；截断恢复额度最多 8192。
- 不执行或签名 length/max_tokens 结束的部分规划。
- 缺失月份/指标不补零，CVR=订单/点击，EPC=联盟佣金/点击。
- 不提交、推送、创建 PR 或部署；不修改缓存、凭据或数据库结构。
